# 자연어 답변 평가 진행 방법

## 지금 준비된 것

- `evals/natural_dev.jsonl`: AI가 작성한 개발 점검 질문 31개. 설계학점 12학점의 구성 과목 질문을 포함한다. 실제 학생이 작성한 질문으로 표시하지 않는다.
- 관리자 페이지 **평가질문관리**: 실제 질문·작성 출처·기대 답변 메모를 등록하고 기본 답변 수집을 실행한다.
- `evaluate_natural.cmd`: 기본 답변 모드로 답변·출처·검색 근거·실행시간을 기록한다. API를 호출하지 않는다.
- 관리자 페이지 **자연어답변평가**: 원문과 답변을 대조하고 수동 채점한다.
- 각 실행에 질문 파일 해시, 코드·규정·문서 본문 해시, 검색 방식, 실제 처리 경로를 기록한다. 실행 오류는 별도로 표시하며 정답으로 계산하지 않는다.
- `evals/local_runs/`: 로컬 실행·채점 결과. GitHub와 배포 ZIP에서 제외된다. 필요한 결과만 관리자 화면에서 직접 내보낼 수 있다.

## 처음 사용하기

1. 프로그램을 종료하고 `start.cmd`로 다시 실행한다.
2. 이미 수집한 결과는 왼쪽 **자연어답변평가** 페이지에서 확인한다. 관리자 비밀번호는 기존 관리자 기능과 같다.
3. **평가질문관리**에서 ‘기본 개발 예시’를 선택하고 **답변 수집 실행**을 누른다. `evaluate_natural.cmd`로도 실행할 수 있다. 모델이 처음 로딩될 때 시간이 걸릴 수 있다.
4. 실행 파일을 선택하고 질문마다 공식 원문을 열어 확인한다. 출처에 표시된 문장이 답변에 실제로 주장한 모든 조건을 뒷받침하는지 확인한다.
5. 기대 행동, 정확성, 근거 일치, 적용 범위 처리를 선택하고 평가자 별칭·기대 정답과 출처·채점 이유를 적어 저장한다.
6. 채점한 표본의 결과를 JSON으로 내려받을 수 있다. 질문이나 답변에 개인정보가 있다면 외부 공유 전에 제거한다.

## 채점 기준

| 항목 | 평가 방법 |
|---|---|
| 정확성 | 질문에 맞는 값과 조건을 빠짐없이 답하면 정답. 일부 누락이면 부분 정답. 잘못된 값·무관한 답변이면 오답. 정보 부족 질문에서 정확한 추가 질문/보류를 한 경우도 기대 행동에 맞으면 정답으로 평가할 수 있다. |
| 근거 일치 | 원문이 답변의 모든 주장을 뒷받침하면 일치. 출처는 있으나 일부 조건을 뒷받침하지 못하면 부분 일치. 원문과 다르거나 무관하면 불일치. 사실 주장 없이 보류한 경우만 해당 없음. |
| 적용 범위 | 학과·입학연도·과정·이수시기·개정 관계를 올바르게 처리했는지 확인한다. 모르는 조건을 추측하거나 옛 규정을 무조건 최신으로 제시하면 부적절. |
| 기대 행동 | 자료가 충분하면 답변, 질문 조건이 부족하면 추가 질문, 필요한 원문이 없거나 개인 판정 불가라면 보류로 사전에 정한다. |

정답률 = 정답으로 채점한 수 / 채점 완료 수. 부분 정답은 분자에 넣지 않는다. 미채점은 분모에도 넣지 않는다. 근거 일치율에서는 ‘해당 없음’을 제외한다. 보류·추가 질문 처리율은 그 행동이 기대되는 표본만 분모로 사용한다. 각 분모와 미채점 수를 함께 보고한다. `0%`와 `미채점`은 다르다.

한 사람이 자기 구현을 채점하면 편향이 있을 수 있다. 가능하면 다른 검토자가 일부 질문을 독립적으로 다시 채점하고, 불일치 이유와 합의 결과를 별도로 기록한다. 교수/조교에게 답의 근거 검토를 받을 수 있다면 더욱 좋다.

## 실제 학생 질문으로 확장하기

1. 학생에게 프로그램의 예시 답변을 보여주기 전에 자연스럽게 궁금한 질문을 적어 달라고 한다. 이름·학번·성적표는 받지 않는다. 공유받은 질문을 평가에 사용하는 취지를 설명한다.
2. 먼저 10~20개를 수집해 문장 표현과 주제를 확인한다. 졸업학점, 필수과목, 외국어, MSC/설계, 개정 규정, 학번/과정 모호함, 자료 밖 질문을 포함하되 질문을 원하는 답에 맞춰 고치지 않는다.
3. 원문과 대조해 기대 행동·정답·근거 문서·페이지/URL을 정한다. 자료가 없으면 없다고 기록한다.
4. 같은 질문의 표현만 바꾼 문항은 하나의 `group`으로 묶는다. 동일 그룹은 dev/test를 나누지 않는다.
5. 개발용 dev로만 수정하고, 별도로 보관한 test는 구현을 고정한 뒤 최종 평가에 사용한다. test를 보고 수정했다면 그 결과를 독립 평가로 계속 주장하지 않는다.

**평가질문관리** 화면에서 질문, 작성 출처, 주제, 질문 그룹을 입력하고 **질문 저장**을 누른다. 입학연도·과정은 실제로 확인한 경우만 입력한다. 기대 답변·추가 질문/보류 여부와 근거는 메모에 적으며, 답변 평가 화면에서도 확인할 수 있다. 메모 자체가 검증된 정답으로 자동 처리되지는 않는다.

작성 출처는 자동으로 지정하지 않는다. 같은 질문이나 동일 그룹의 dev/test 중첩은 기본 예시를 포함해 검사한다. 문장의 의미가 같은지는 자동으로 판정하지 않으므로 ‘기존 그룹 확인’을 보고 같은 그룹으로 지정한다. 등록된 질문은 실행 파일에도 복사되므로 각 실행 당시의 질문과 메모가 보존된다.

등록 후 수집할 질문을 **직접 등록한 질문**으로 바꾸고 수집 구분(dev/test)과 검색 방식을 선택해 **답변 수집 실행**을 누른다. 이어 **자연어답변평가에서 답변 채점하기**를 누른다. 수집 중에는 공유 검색 설정과 문서 버전 보호를 위해 다른 검색·문서 반영이 잠시 대기할 수 있다.

질문은 `evals/private_questions/student.jsonl`에 저장된다. 직접 JSONL을 준비하는 경우에도 아래 형식을 사용할 수 있다. 아래는 형식 설명이며 실제 학생 발언이 아니다. `origin`은 실제 작성 출처에 맞게 지정한다.

```json
{"id":"S001","group":"english-alternative-2025","category":"개정 규정","question":"학생이 실제로 작성한 질문","department":"소프트웨어융합학과","admission_year":null,"track":null,"split":"dev","origin":"student","reference_note":"원문과 대조해 기대 행동과 확인 근거를 기록"}
```

실행 예:

```powershell
.\.venv\Scripts\python.exe -m scripts.evaluate_natural --dataset evals/private_questions/student.jsonl --split dev --mode hybrid
```

`--mode dense`로 별도 실행할 수 있다. 다만 수동 검토 규정과 정확한 과목 조회는 두 방식이 공유한다. 같은 결과가 나오는 문항을 근거로 하이브리드 검색이 우수하다고 결론 내리지 않는다. 일반 검색 문항의 처리 경로와 결과를 구분해서 분석한다.

## 이번 개발 점검 결과 (2026-09-12)

30개 질문으로 두 번 기본 답변을 수집했고 두 실행 모두 실행 오류는 0건이었다. 첫 실행 결과를 보고 아래 사례를 수정한 후 같은 개발 질문으로 다시 실행했다. 두 번째 실행은 독립된 최종 평가가 아니다. 수동 채점은 0건이며 정확도는 아직 산출하지 않았다.

| N022 | ‘자료구조’의 축약 과목명이 무관한 PDF로 연결됨 | 유일한 정식 과목 ‘자료구조 및 프로그래밍 실습’의 CSV 정보 반환; 여러 과목이면 추가 질문 |
