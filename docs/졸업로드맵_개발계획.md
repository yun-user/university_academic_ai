# 개인별 졸업요건 점검과 이수계획

제출 목표: **2026년 11월 9일**. 대상: 홍익대학교 세종캠퍼스 소프트웨어융합학과 **2020학번, 심화·일반과정**. 첫 버전은 단일전공 신입학 학생으로 범위를 한정한다.

## 현재 구현

**2026-10-07 추가:** 별도 프론트엔드·백엔드·DB 필수 요구에 맞춰 React/TypeScript + FastAPI + SQLite 웹앱을 추가했다. `setup_web.cmd`와 `start_web.cmd`로 실행한다. 아래의 세션 메모리·백업 설명은 기존 Streamlit 경로에 관한 것이며, 새 웹앱은 명시적인 저장 버튼으로 로컬 DB에 이수 내역과 기본 계획을 저장한다. [새 구조·DB 설계·LLM 상담·검증 범위](졸업로드맵_웹앱구조와시연.md)를 기준으로 두 실행 경로를 구분한다.

앱의 **졸업로드맵** 메뉴에서 사용할 수 있다. 기존 근거 검색은 유지한다. 기본 모드는 임베딩이나 외부 LLM 없이 계산하므로 색인이 없어도 동작한다. 선택적으로 LLM 맞춤 추천을 켜면 희망 진로·수강 선호에 따른 우선순위와 설명을 받는다.

1. 가상 예제, 지정 CSV, 수동 입력으로 과목별 이수내역을 작성한다.
2. 과정별 기준에 따라 현재 인정학점·부족학점과 영역별 요건을 계산한다.
3. 학교에서 확인한 개인 필수과목 목록, 졸업논문·어학 제출 상태를 별도로 입력한다.
4. 추천 후보의 개설 학기·학점·선수과목을 수정하고 추천에서 제외하거나 후보를 추가한다.
5. 학기 수와 학점 한도를 정해 로드맵을 생성한다. 각 추천의 이유와 배치 후에도 남는 항목을 표시한다.
6. 이수내역 CSV, 점검 결과·로드맵 JSON, 전체 입력 백업 JSON, 인쇄용 HTML 보고서를 내려받는다. 전체 입력 백업으로 입력·계획 조건을 복원한다.
7. 학교에서 확인한 대체과목 관계를 적용 과정·수강기간·근거와 함께 등록한다. 해당 기간의 실제 취득내역으로 필수요건을 점검하고 적용 근거를 표시한다.

입력 자료는 Streamlit 세션 메모리에서만 처리한다. 서버 파일, 검색 corpus, 모델, 예제 데이터에 개인 성적을 저장하지 않는다. 이름·학번 열은 받지 않는다. 가상 예제는 특정 학생의 이수내역을 사용하지 않았다. 새로고침·세션 종료 전에 전체 입력 백업을 내려받아 보관한다.

## 계산 원칙

- F/F0/NP와 성적 미확정, 수강중, 인정제외 과목은 현재 취득학점에서 제외한다.
- 중복·재수강 또는 동일과목으로 묶인 취득내역이 여러 건이면 모두 보류한다. 인정할 한 건만 남기고 나머지를 인정제외로 표시한다. 연쇄 동일과목 관계도 중복 집계하지 않는다.
- 선택 대안과 동일과목을 구분한다. 교과과정에서 ‘중 택1’로 제시한 과목을 동일과목으로 자동 묶지 않는다. 다만 대안 중 하나를 이미 취득·수강중이면 다른 대안을 자동 추천하지 않는다. 후보 표의 `선택대안학수번호`로 조정한다. 이 설정은 기존 취득학점의 중복 인정 여부를 결정하지 않는다.
- 후보 표에 공식 확인한 동일과목 관계를 입력하면 계획 후 예상 점검과 선수조건에도 같은 관계를 적용한다. 현재 이수내역의 점검은 입력 이수내역만을 사용하므로, 해당 관계를 이수내역에도 반영해야 인정 기준이 일치한다.
- 전문교양·일반 교양선택·특성화교양을 구분한다. 교양선택을 전문교양 최소학점에 자동 산입하지 않는다. 교양 인정 상한은 총 졸업인정학점에 반영한다.
- 설계 인정학점은 전공학점에 포함된 부분이다. 총학점에 한 번 더 더하지 않는다. 수강 당시의 설계 인정학점은 사용자가 확인해서 입력한다.
- 교양 영역 개수, 필수 영역, 과학 실험 과목, 기초·종합설계, 개인 필수목록을 별도로 검사한다.
- 필수과목 목록을 비워두는 것만으로 필수 이수를 완료했다고 표시하지 않는다.
- 현재 이수내역과 수강중 과목 통과 가정을 분리한다. 수강중 통과 가정은 로드맵에만 적용한다.
- 자동 로드맵은 입력된 개설 학기, 학점 한도, 이전 학기에 이수해야 하는 선수조건, 중복 이수를 검사하는 탐욕적 휴리스틱이다. 최적·최단 졸업을 보장하지 않는다.
- 입력한 후보로 요건을 채울 수 없거나 선수과목 순환·누락이 있으면 남은 항목을 그대로 보여준다. 모르는 과목이나 추가 학점을 지어내지 않는다.

## 다음 단계 진행: 기간별 대체인정 (2026-10-05)

개발계획의 ‘실제 인정 규칙과 입력 편의 보강’ 중 대체인정 입력·계산을 구현했다. 원래 필수과목, 대체 이수과목, 심화/일반과정, 인정되는 수강기간, 근거와 사용자 확인 상태를 기록한다. 확인되지 않은 관계와 다른 과정의 관계는 적용하지 않는다. 적용 기간은 시작·종료 학기를 포함하며 하계·동계 순서를 반영한다.

대체인정은 필수과목 요건만 충족시킨다. 실제 학점·이수구분·설계 인정학점은 입력 이수내역 그대로이며, 동일과목 중복 처리나 선수조건 면제로 확대하지 않는다. 반대 방향·연쇄 대체·동일과목 별칭으로도 자동 확대하지 않는다. JSON 결과에 설정과 실제 적용 근거가 함께 저장된다. CSV는 이수내역만 저장한다. 이 단계에서는 JSON 재불러오기가 없었으며, 아래 후속 구현에서 전체 입력 백업·복원을 추가했다.

전체 자동 테스트 **364개 통과**(16.85초), 로드맵 관련 **61개**다. 실제 브라우저에서 가상 관계 등록, 적용 근거 표시, 기존 21학점 유지, 결과 JSON 다운로드 및 필수요건 충족 결과를 확인했다. 가상 관계는 검증용 브라우저 세션에서만 입력했고 기본 학교 규칙에 추가하지 않았다.

## 2026-10-05 LLM 맞춤 추천 추가

이수한 과목과 희망 진로를 바탕으로 OpenAI가 후보 과목 우선순위·추천 이유·다음 행동을 제안하고 계산기가 학기별로 배치한다. 기본 계산과 LLM 모드를 화면에서 구분한다. 잘못된 학수번호·이수 완료·제외·중복 제안이나 API 오류 시 기본 계산으로 돌아간다. 생성 버튼을 누를 때만 요청하며 화면 재실행으로 재호출하지 않는다.

전송 전 요약 미리보기와 동의 기능을 추가했다. 성적등급·학생 식별정보·대체인정 메모·API 키를 요청 본문에서 제외한다. API 키는 백업이나 보고서에 포함하지 않는다. 백업의 희망 사항은 복원하되 전송 동의는 해제한다. LLM 설명도 결과 JSON·인쇄용 보고서에 함께 저장할 수 있다.

전체 **399개 테스트 통과(23.23초)**. 모의 응답으로 우선순위의 실제 반영, 개설·선수·학점 제한 유지, 비정상 응답·통신 실패의 기본 계산 전환, 민감 필드 제외, 중복 호출 방지, UI 동의 절차를 검증했다. 브라우저에서 기존 OpenAI 설정을 불러오는 것까지 확인했다. 실제 유료 API 호출 및 LLM 설명의 실증 정확도 평가는 수행하지 않았다.

2026-10-06 재개 후 배포 검증: 별도 경로에 압축을 푼 LLM 실행본에서 **96개 테스트 통과(8.39초)**. 기존 가상환경으로 검사했으며 새 PC 설치 시험은 아니다. 최종 ZIP의 소스·규정·의존성 파일이 이 검증본과 같은지 해시로 확인한다.
