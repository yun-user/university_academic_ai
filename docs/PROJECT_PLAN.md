## 1. 핵심 결론

MVP는 단일 Streamlit 애플리케이션으로 실행되는 **모듈러 모놀리스**로 만든다. 화면, 유스케이스, 도메인 규칙, 외부 기술 어댑터를 분리해 나중에 FastAPI, 다른 벡터 DB, 다른 LLM으로 교체할 수 있게 한다.

| 결정 | 채택안 | 이유 |
|---|---|---|
| 애플리케이션 구조 | Streamlit 기반 모듈러 모놀리스 | 졸업작품 범위에서 배포와 디버깅이 단순하면서 계층 분리는 유지 가능 |
| 기준 데이터 | 원본 불변 저장소 + SQLite 문서 카탈로그 | 문서 버전, 페이지, 작업 상태, 삭제 이력, 출처를 Chroma에만 맡기지 않기 위함 |
| 벡터 DB | ChromaDB `PersistentClient` | 로컬 영속성, 메타데이터 필터, upsert/delete가 MVP에 적합 |
| 키워드 검색 | 한국어 토큰화 기반 BM25 | 학수번호, 학점, 날짜, 규정 용어처럼 exact match가 중요한 질문 보완 |
| 검색 결합 | Dense + BM25의 Weighted RRF | 서로 다른 원점수 분포를 직접 합산하지 않고 안정적으로 순위 결합 |
| 임베딩 기준선 | `intfloat/multilingual-e5-base` | Sentence Transformers 호환, 다국어 검색용, CPU MVP의 합리적 기준선 |
| 임베딩 비교군 | `BAAI/bge-m3` | 더 긴 입력과 다국어 검색 성능을 비교하는 발표용 실험 후보 |
| 재정렬 | 설정 가능한 Cross-Encoder, 실패 시 RRF 유지 | 정밀도를 높이되 CPU·메모리 제약에서 안전하게 비활성화 가능 |
| 답변 생성 | 선택적 OpenAI 또는 OpenAI 호환 LLM | API 키가 없을 때에도 등록·검색·디버그가 정상 동작해야 함 |
| 인용 방식 | 주장별 evidence ID + 서버 조립 출처 | LLM이 문서명, 페이지, URL을 지어내지 못하게 함 |
| 근거 부족 | 생성 전·후 이중 게이트 | 낮은 관련도, 조건 불일치, 출처 검증 실패 시 추측 답변 차단 |
| 이미지형 PDF | 페이지별 스캔 감지 + `kor+eng` OCR + 품질 게이트 | 제공된 4쪽 교과과정 PDF가 전 페이지 이미지형이므로 필요 |
| 삭제 | 검색 비활성화와 soft delete 기본 | 원본을 자동 삭제하거나 덮어쓰지 않는 안전 규칙 준수 |

## 2. 프로젝트 목표와 비목표

### 2.1 목표

- 대학 학사규정, 졸업요건, 장학금, 수강신청 공지, 학과 안내문을 PDF·TXT·공개 웹에서 등록한다.
- 질문과 관련된 근거를 벡터 검색과 키워드 검색으로 찾는다.
- 검색된 근거만 사용해 답변하고, 모든 핵심 주장에 실제 출처를 연결한다.
- PDF는 1부터 시작하는 물리 페이지, 웹 공지는 원문 URL과 게시일을 유지한다.
- 근거가 부족하거나 적용 시점·학과·입학연도를 확정할 수 없으면 답변을 생성하지 않는다.
- LLM API 키가 없어도 문서 등록, 청크 미리보기, 검색, 출처 확인, 검색 디버그, 검색 평가를 실행한다.
- 관리자에게 문서 상태, 실패 페이지, 중복, 개인정보 가능성, OCR·표 품질을 투명하게 보여준다.

### 2.2 비목표

- 개인 학적 시스템, 성적, 등록금 납부 내역을 조회하지 않는다.
- 로그인, CAPTCHA, SSO 또는 접근 제어를 우회하지 않는다.
- 등록되지 않은 일반 상식으로 학사 규정을 보완하지 않는다.
- 학교 담당 부서의 공식 해석을 대체하지 않는다.
- MVP에서 다중 학교, 대규모 분산 처리, 완전 자동 전 사이트 크롤링을 구현하지 않는다.
- 검증되지 않은 OCR 표에서 숫자·학점·날짜 답변을 단정하지 않는다.

## 3. 제공 자료 사전 분석과 설계 영향

PDF는 텍스트 추출 결과와 렌더링 이미지를 함께 점검했다. 이 결과는 추후 테스트 fixture와 수용 기준으로 사용한다.

| 자료 | 확인 결과 | 반드시 반영할 설계 |
|---|---|---|
| `학교정보.txt` | BOM 없는 UTF-8, 홍익대학교 세종캠퍼스·소프트웨어융합학과·학교/학과 URL 포함 | 학교·캠퍼스·학과와 허용 도메인의 초기 설정 자료로 사용. 학사 답변의 직접 근거로는 사용하지 않음 |
| `2024_장학금선정기준.pdf` | 2쪽, 텍스트 레이어 존재, 추출문에 `U+0000` 제어문자 다수 | 제어문자 제거, 목록·날짜·숫자 보존, 페이지별 인용 회귀 테스트 필요 |
| `(20260211)2026 교과과정책자 합본(안)_f1.pdf` | 237쪽 중 대부분은 텍스트가 있으나 표 중심. 일부 표지·간지는 무텍스트. PDF 물리 193·194쪽의 인쇄 표기는 `A-6`, `A-7` | 페이지 단위 추출 경로, 표 전용 직렬화, 물리 페이지와 인쇄 페이지 라벨 분리, 표 품질 검증 필요 |
| `교과과정.pdf` | 4쪽 모두 전체 페이지 이미지, 일반 텍스트 0자, 교과목·학점·학수번호 표 포함 | 페이지별 OCR 분기 필수. OCR 미설치·저품질이면 빈 문서로 활성화하지 않고 관리자 검토 상태로 전환 |
| 두 교과과정 자료의 관계 | 4쪽 발췌본과 237쪽 책자의 내용이 부분 중복일 가능성이 높음 | 파일 SHA-256 외에 청크 겹침률과 근접·부분 중복 그룹이 필요 |

중요한 결론은 PDF 하나에 하나의 추출 방식을 적용하지 않는다는 것이다. 같은 PDF 안에서도 `DIRECT_TEXT`, `TABLE`, `OCR_REQUIRED`, `EMPTY_EXPECTED`, `NEEDS_REVIEW`를 페이지별로 판정한다.

## 4. 설계 가정

불명확한 사항은 다음 기본값으로 결정한다. 구현 또는 평가 결과가 달라지면 설정과 의사결정 기록을 갱신한다.

| 주제 | 기본 가정 |
|---|---|
| 학교 범위 | 초기에는 홍익대학교 세종캠퍼스 한 곳 |
| 학과 범위 | 소프트웨어융합학과 우선, 공통 학사자료도 검색 가능 |
| 언어 | 질문과 문서는 한국어 중심, 학수번호·영문 교과목명 혼합 |
| 데이터 규모 | 단일 PC, 수만 청크 이하 |
| 실행 환경 | 로컬 또는 소규모 단일 서버, 관리자 1명 우선 |
| 페이지 기준 | `page_number`는 1부터 시작하는 PDF 파일 물리 페이지 |
| 인쇄 쪽수 | `printed_page_label`에 별도 저장하고 UI에서 병기 |
| 시간 기준 | 저장은 UTC, 사용자 표시는 Asia/Seoul |
| 현재 학기 | 서버 날짜로 임의 추정하지 않고 학교 학사 캘린더 설정으로 해석 |
| 문서 효력 | 게시일과 효력일은 다를 수 있으며, 관리자 확인값을 우선 |
| 원본 보존 | append-only에 가깝게 보존. 삭제 UI는 기본적으로 검색 비활성화 |
| OCR | 300 DPI, `kor+eng`; 한국어 Tesseract 언어팩을 배포 전 준비 |
| 웹 수집 | 관리자 수동 실행, 동시 요청 1, 기본 2초 간격, 최대 50개 상세 공지/실행 |
| 업로드 제한 | 기본 50 MB, PDF 1,000쪽. 실제 장비 측정 후 조정 |
| 임베딩 | 모델명, revision, 차원, prefix, 정규화 여부를 fingerprint로 관리 |
| LLM | API 키가 있으면 생성 모드, 없으면 검색 전용 모드 |
| 질문 로그 | 기본은 원문 영구 저장 안 함. 평가셋과 사용자 동의 로그만 별도 보관 |
| 임계값 | 임의 cosine 상수 대신 dev 평가셋으로 보정 |
| 관리자 인증 | 로컬 MVP는 환경변수 기반 최소 인증, 외부 공개 전 SSO/RBAC 필요 |

## 5. 전체 서비스 구조

서비스는 다음 네 계층으로 나눈다.

1. **Presentation**: Streamlit 사용자·관리자·평가 화면
2. **Application**: 등록, 수집, 검색, 질문 답변, 삭제, 재색인, 평가 유스케이스
3. **Domain**: 문서·페이지·청크·검색결과·근거·답변 모델과 정책
4. **Infrastructure**: PyMuPDF, OCR, requests/BeautifulSoup, SQLite, Chroma, BM25, Sentence Transformers, 선택적 LLM

원본 파일과 SQLite 카탈로그를 정본으로 취급한다. Chroma와 BM25 색인은 언제든 원본·카탈로그에서 다시 만들 수 있는 파생 데이터다. 색인 갱신은 새 버전을 스테이징한 뒤 검증하고 활성 포인터를 바꾸는 방식으로 수행한다.

자세한 컴포넌트와 인터페이스는 `ARCHITECTURE.md`를 따른다.

## 6. 사용자 흐름

1. 사용자가 질문, 학과, 범주 또는 학년·학기 조건을 입력한다.
2. 시스템이 빈 질문, 과도한 길이, 범위 밖 질문, 개인 학적 필요 질문을 분류한다.
3. 질문에서 학과, 입학연도, 학기, 기준 시점, 필요한 답의 종류를 추출한다.
4. Chroma 벡터 검색과 BM25 키워드 검색을 실행한다.
5. RRF로 결합하고 중복·구버전 결과를 정리한 뒤 선택적으로 재정렬한다.
6. 근거 충분성 게이트가 관련도, 필수 숫자·날짜, 학과·연도 일치, 문서 효력, 출처 메타데이터를 검사한다.
7. 근거가 부족하면 다음 문구로 종료한다.

> 등록된 학사 자료에서 확인할 수 없습니다. 학교 학사 담당 부서에 문의해 주세요.

8. LLM 키가 없거나 사용자가 검색 전용 모드를 선택하면 AI 요약 없이 관련 원문 카드만 보여준다.
9. LLM을 사용할 수 있으면 근거 ID가 포함된 구조화 답변을 생성한다.
10. 주장별 인용, 숫자·날짜·부정 표현, 원문 substring, 페이지·URL을 검증한다.
11. 검증을 통과한 답변만 핵심 답변, 상세 설명, 출처, 원문, 신뢰도, 확인 필요 사항과 함께 표시한다.

사용자 화면에서 `자료 없음`, `범위 밖`, `개인 정보 필요`, `LLM 미설정`, `시스템 오류`를 서로 다른 상태로 표시하되, 자료 부족 최종 응답은 지정 문구를 정확히 유지한다.

## 7. 관리자 흐름

### 7.1 파일 등록

1. 관리자가 PDF 또는 TXT를 선택하고 제목, 학과, 범주, 게시일을 입력한다.
2. 확장자, MIME, 매직 바이트, 크기, 페이지 수를 검증한다.
3. 스트리밍 SHA-256을 계산하고 내부 ID 경로에 원본을 복사해 불변 보존한다.
4. 정확·내용·부분 중복을 검사한다.
5. 페이지별 텍스트·표·스캔 여부, 제어문자, 개인정보 가능성을 미리 본다.
6. OCR·표 품질 경고와 실패 페이지를 관리자가 확인한다.
7. 청크, 임베딩, Chroma, BM25 스테이징 색인을 생성한다.
8. 청크 수, 벡터 수, 필수 메타데이터, 샘플 검색을 검증한 후 활성화한다.

### 7.2 웹 공지 수집

1. 시작 URL, 허용 도메인, 최대 수집 수, 요청 간격을 입력한다.
2. HTTP(S), DNS, 사설 IP, 리다이렉트, robots.txt, 로그인 필요 여부를 검사한다.
3. 목록 URL과 발견 상세 URL을 미리 보여주고 제외 이유를 표시한다.
4. 승인된 공개 상세 페이지만 순차 수집한다.
5. HTML 원본 스냅샷, 정제 본문, 제목, 게시일, canonical URL, 첨부 링크를 보존한다.
6. 같은 URL의 내용 변경은 새 버전으로 등록하고 이전 원본을 덮어쓰지 않는다.

### 7.3 문서 관리

- 목록에서 학과, 범주, 상태, 경고, 게시일, 인덱스 버전으로 필터링한다.
- `삭제`는 먼저 검색 비활성화와 색인 제거를 수행하고 원본은 보존한다.
- 재색인은 새 인덱스를 검증한 뒤 전환하며 실패 시 기존 인덱스를 계속 사용한다.
- 모든 관리자 변경은 작업 ID, 작업자, 시각, 대상 버전, 결과를 감사 로그에 남긴다.

```text
→ 원문/표시문/정규화문 분리
→ 페이지·절·표 경계 청크
→ 메타데이터 무결성 검사
→ SQLite 정본 저장
→ 임베딩 + Chroma + BM25 스테이징
→ 개수·샘플 검색 검증
→ 활성 버전 전환
```

일반 문단은 한 물리 페이지 안에서 목표 450-700자, 최대 약 900자, 80-120자 겹침으로 시작한다. 실제 임베딩 토크나이저 길이가 모델 한도의 70-80%를 넘지 않게 조정한다. 표는 헤더와 5-10개 행을 묶고 분할할 때마다 헤더와 학과·학년·학기 문맥을 반복한다.

## 9. RAG 답변 생성 흐름

```text
질문 검증·범위 분류
→ QueryPlan 생성
→ Dense 후보 40 + BM25 후보 40
→ Weighted RRF(k=60, 초기 가중치 0.55/0.45)
→ 활성 버전·조건 필터·중복 collapse
→ 선택적 Cross-Encoder 상위 20 재정렬
→ 최종 근거 5-8개 선택
→ 생성 전 Evidence Gate
→ [거절 | 검색 전용 | LLM 구조화 생성]
→ 주장-근거·원문·숫자·날짜·극성 검증
→ 신뢰도 등급과 출처 카드 조립
```

초기 수치는 시작값일 뿐이다. dev 평가셋에서 조정하고 설정 파일에 기록한다. Dense, BM25, RRF, reranker 원점수는 관리자 디버그 화면에 각각 표시하고 일반 사용자에게 정답 확률로 노출하지 않는다.

## 10. 출처와 답변 표시 원칙

답변은 다음 순서로 표시한다.

1. 핵심 답변
2. 상세 설명
3. 답변 신뢰도와 산정 이유
4. 확인이 필요한 사항
5. 출처 목록
6. 관련 원문 인용

PDF 출처 예시는 `2026 교과과정책자 · PDF 파일 기준 193쪽 · 문서 표기 A-6`이다. 웹 출처는 문서명, 게시일, 수집일, 원문 URL을 표시한다. TXT처럼 페이지와 공식 URL이 없는 자료는 검색 보조 자료로는 쓸 수 있으나, 최종 학사 주장에 필요한 페이지/URL 출처를 대체하지 않는다.

LLM은 `E1`, `E2` 같은 evidence ID만 반환한다. 실제 문서명, 페이지, URL, 게시일, content hash는 서버가 카탈로그에서 조립한다. 모든 검증 가능한 문장에는 최소 하나의 evidence ID가 있어야 한다.

## 11. 근거 부족 판단

다음 중 하나라도 해당하면 생성 전 거절한다.

- 검색 후보가 없거나 보정된 관련도가 기준 미만이다.
- 질문에 명시된 학과, 입학연도, 학년, 학기, 기준 시점과 맞는 근거가 없다.
- `몇 학점`, `언제`, `얼마` 질문인데 숫자·날짜·단위 근거가 없다.
- 현재 정보를 묻는데 유효한 최신 문서가 없거나 2024 자료만 있다.
- 서로 충돌하는 문서의 적용 버전을 결정할 수 없다.
- PDF인데 페이지가 없거나 웹 공지인데 URL·게시일이 없어 인용 계약을 충족하지 못한다.
- OCR 또는 표 레이아웃 품질이 숫자성 답변 기준에 못 미친다.
- 개인 학적 조회가 필요하거나 서비스 범위 밖이다.

생성 후에는 다음을 검사한다.

- 모든 핵심 주장에 유효 evidence ID가 있는가.
- 인용문이 저장된 정규화 원문의 실제 부분 문자열인가.
- 숫자, 날짜, 학점, `이상/이하`, `가능/불가`, 학과, 연도가 근거와 일치하는가.
- 인용 청크가 실제 생성 컨텍스트에 포함됐는가.
- 답변 생성 시점의 `content_hash`가 현재 활성 버전과 같은가.

보조 문장만 실패하면 제거 후 다시 검증할 수 있다. 핵심 주장이 실패하면 전체 답변을 폐기하고 지정 거절문으로 전환한다.

## 14. ChromaDB와 FAISS 결정

| 항목 | ChromaDB | FAISS |
|---|---|---|
| 로컬 영속성 | `PersistentClient` 제공 | 인덱스 직렬화와 수명주기를 직접 설계 |
| 메타데이터 | 레코드와 함께 저장·필터 | 별도 DB와 ID 매핑 필요 |
| upsert/delete | 컬렉션 API 제공 | 인덱스 종류에 따라 제약과 추가 구현 발생 |
| MVP 복잡도 | 낮음 | 상대적으로 높음 |
| 대규모 고성능 튜닝 | 충분하지만 전문성은 제한 | CPU/GPU와 다양한 ANN 인덱스에 강점 |
| 본 프로젝트 적합성 | 높음 | 수백만 이상 벡터·GPU 최적화 단계의 대안 |

따라서 MVP는 ChromaDB를 사용한다. 다만 상위 계층은 `VectorStorePort`만 의존하고, Chroma의 distance·metadata 형식을 직접 노출하지 않는다. 향후 FAISS, pgvector, OpenSearch로 교체할 수 있게 공통 `SearchHit` 계약을 사용한다.

## 15. 단계별 구현 순서와 완료 기준

전체 일정은 1인 개발 기준 약 10-12주와 2주 완충을 가정한다. 각 단계는 직전 단계의 자동 테스트를 통과해야 다음으로 넘어간다.

### 1단계: 프로젝트 기본 구조와 설정

**구현 범위**

- 최종 폴더 구조, 패키지, 설정, 로깅, 예외, DTO, 포트 정의
- `.env.example`, `config/defaults.toml`, SQLite schema version
- API 키가 없는 `retrieval-only` 부팅 모드

**완료 기준**

- 설정 누락 시 비밀값 없이 안전한 오류 또는 기능 저하가 동작한다.
- 모델명, revision, 경로, top-K, 크롤 제한이 코드에 직접 고정되지 않는다.

### 2단계: PDF 등록과 페이지별 텍스트 추출

**구현 범위**

- 원본 불변 저장, SHA-256, 문서·버전·페이지 카탈로그
- PyMuPDF 블록 추출, 물리 페이지, 인쇄 라벨, 제어문자 정제
- 스캔·혼합 PDF 감지, OCR 분기, 표 후보와 품질 상태
- TXT의 UTF-8/UTF-8-SIG 우선 처리, 인코딩 fallback과 안정적인 줄 위치 보존

**완료 기준**

- 장학금 PDF 2쪽이 `U+0000` 없이 페이지별 추출된다.
- 이미지형 교과과정 4쪽이 OCR 필요로 탐지되고, OCR 미설치 시 활성화되지 않는다.
- 237쪽 책자의 PDF 193쪽과 `A-6` 라벨이 구분된다.
- `학교정보.txt`가 UTF-8로 깨짐 없이 읽히고 프로젝트 seed 설정과 답변 evidence의 용도가 구분된다.

### 3단계: 청크 생성과 벡터 DB 저장

**구현 범위**

- 페이지·절·표 인식 청커, 모든 필수 메타데이터
- Sentence Transformers 임베딩과 fingerprint
- Chroma 스테이징/활성 컬렉션, BM25 색인, SQLite 정본

**완료 기준**

- PDF 청크는 한 물리 페이지를 넘지 않는다.
- 표 청크에는 헤더와 행 문맥이 반복된다.
- 활성 청크 수, Chroma 벡터 수, BM25 레코드 수가 일치한다.

### 4단계: 질문 검색과 출처 반환

**구현 범위**

- QueryPlan, 학과·연도·학기 필터
- Dense/BM25 병렬 검색, RRF, 중복 collapse, 선택적 reranker
- 검색 결과에 문서명, 페이지/URL, 원문, 각 단계 점수 반환

**완료 기준**

- API 키 없이 샘플 질문의 관련 문서와 물리 페이지가 표시된다.
- 구버전·다른 학과·목차 hard negative가 디버그 화면에서 구분된다.

### 5단계: LLM 답변 생성과 근거 부족 거절

**구현 범위**

- 선택적 OpenAI 호환 클라이언트와 Null client
- 구조화 프롬프트, Evidence Gate, Citation Builder/Verifier, Confidence
- 정확한 지정 거절문과 claim-evidence 계약

**완료 기준**

- LLM이 문서명·페이지·URL을 생성하지 않고 서버 메타데이터가 조립한다.
- 핵심 주장 인용 검증 실패 시 답변이 노출되지 않는다.
- 최신 근거가 없는 `이번 학기` 질문이 거절된다.

### 6단계: Streamlit 사용자 화면

**구현 범위**

- 질문·필터·예시 질문, 답변 섹션, 출처 카드, 원문 펼치기
- 검색 전용 배너, 신뢰도 등급, 확인 필요 사항, 오류 상태

**완료 기준**

- PDF와 웹 출처 형식이 구분되고 내부 절대 경로가 노출되지 않는다.
- 미검증 답변이 스트리밍 중 잠시라도 표시되지 않는다.

### 7단계: 관리자 문서 관리 화면

**구현 범위**

- 업로드 미리보기, 개인정보·OCR·표 경고, 등록 문서 목록
- 영속 작업 상태, 실제 페이지·청크 진행률, soft delete, 재색인

**완료 기준**

- 동일 업로드가 중복 벡터를 만들지 않는다.
- 재색인 실패 시 기존 활성 인덱스가 유지된다.
- 삭제 후 검색에서 빠지지만 원본은 보존된다.

### 8단계: 웹 공지사항 수집

**구현 범위**

- 학교별 WebSourceAdapter, 목록/상세 분리, HTML 정제
- robots, allowlist, 요청 간격, 최대 페이지, SSRF·로그인 차단
- URL·게시일·HTML 스냅샷·첨부 PDF provenance

**완료 기준**

- robots 거부, 로그인 리다이렉트, 사설 IP가 수집되지 않는다.
- selector가 깨졌을 때 빈 공지를 READY로 등록하지 않는다.
- 동일 URL 내용 변경이 새 버전으로 저장된다.

### 9단계: 평가 데이터셋과 평가 화면

**구현 범위**

- 최소 120문항, 권장 300문항의 골드셋
- 검색, 답변, 출처 문서·페이지, 거절, calibration 지표
- 실험 설정·corpus snapshot·결과 저장과 Streamlit 리포트

**완료 기준**

- dev에서 임계값을 선택하고 test는 마지막에 한 번 평가한다.
- 문서/버전/질문군 누출을 막는 group split을 사용한다.
- 모든 대표 지표에 실행 설정과 95% bootstrap 신뢰구간이 연결된다.

### 10단계: 테스트, 리팩터링, 문서화

**구현 범위**

- 단위·통합·계약·E2E·회귀·보안·성능 테스트
- 의존성 고정, 설치·운영·백업·복구·발표 문서
- 연구 실험 결과와 제한점 정리

**완료 기준**

- 핵심 golden query 회귀 기준을 통과한다.
- API 키 없음, OCR 없음, 네트워크 실패, 색인 실패 경로가 검증된다.
- 새 환경에서 README만으로 재현 가능한 발표 데모를 만든다.

## 17. 평가 데이터셋과 지표

### 17.1 데이터셋

- 최소 MVP 120문항: 답변 가능 80, 답변 불가·범위 밖·개인정보 필요 40
- 발표 권장 300문항: 답변 가능 200, 답변 불가 100
- 분할 60/20/20, 동일 paraphrase·사실·문서 버전·표 인접 행은 같은 split
- 최신 학기·최신 버전을 별도 temporal holdout으로 평가
- 골드 근거는 청크 ID에만 묶지 않고 문서 버전, 물리 페이지/URL, 원문 span, content hash로 저장
- 두 명 독립 라벨링, 일부 또는 전체 조정. 답변 가능 여부·문서·페이지 Cohen's kappa 목표 0.80 이상

필수 질문군은 직접 조회, 숫자·날짜, 조건·예외, 표 조회, 복수 근거, 입학연도, 구·신버전, 현재성, 다른 학과, 범위 밖, 개인 학적, prompt injection을 포함한다.

### 17.2 핵심 산식

- `Hit Rate@K = 관련 근거가 top-K에 하나 이상 있는 질문 수 / 답변 가능 질문 수`
- `MRR@K = 질문별 첫 관련 근거 순위의 역수 평균`
- `출처 일치율 = 실제로 주장을 지지하는 인용 수 / 전체 주장-인용 연결 수`
- `출처 페이지 정확도 = 정확한 (document_id, page_number) 인용의 Precision/Recall/F1`
- `잘못된 질문 거절률 = 거절한 답변 불가 질문 수 / 전체 답변 불가 질문 수`
- `거절 정확도 = 실제 답변 불가 질문 수 / 전체 거절 질문 수`
- `답변 가능 질문 응답률 = 답변한 답변 가능 질문 수 / 전체 답변 가능 질문 수`
- `미근거 답변률 = 답변한 답변 불가 질문 수 / 전체 답변 불가 질문 수`
- `Fact-F1 = 원자 사실 Precision과 Recall의 조화 평균`

### 17.4 자동·수동 평가

- 자동: 검색 순위, exact document/page/URL, 숫자·날짜·학점, 지정 거절문, 필수 출력 필드, 인용 substring, citation ID 존재 여부
- 수동: 핵심 답변, 조건·예외·적용 시점, 근거 충실성, 주장-출처 연결, 거절 적절성, 읽기 쉬움
- LLM judge 또는 NLI는 보조 지표로만 쓰고 최종 test 표본은 사람이 확인한다.
- 검색 설정 비교는 paired bootstrap, 거절 정책 비교는 McNemar 검정을 사용한다.

## 19. 보안과 개인정보

- `.env`는 Git에서 제외하고 `.env.example`에는 키 이름만 둔다.
- API 키의 값은 UI, 로그, 예외, 세션 상태, 캐시에 넣지 않는다.
- 업로드는 파일명 대신 생성 ID로 저장하고 확장자, MIME, 매직 바이트, 크기, 페이지 수를 검사한다.
- 원본은 덮어쓰지 않으며 soft delete가 기본이다.
- 주민등록번호, 전화번호, 이메일, 학번, 계좌번호, 주소 후보를 마스킹해 경고한다.
- 주민번호·계좌번호 등 고위험 문서는 격리하고 관리자가 승인하기 전 색인하지 않는다.
- 개인정보 경고 문서는 기본적으로 외부 LLM API에 보내지 않는다.
- 웹 수집은 HTTPS 우선, TLS 검증 유지, 허용 도메인, 사설·loopback·link-local IP 차단, 리다이렉트 재검증을 적용한다.
- robots.txt, 요청 간격, `Retry-After`, 사이트 이용 규칙을 준수하고 로그인·쿠키·CAPTCHA 우회를 하지 않는다.
- HTML 원문은 실행하지 않고 이스케이프하며 `javascript:`, `data:`, `file:` 링크를 차단한다.
- 질문 원문 로그는 기본 비활성화하고, 필요 시 비식별화·보존 기간·동의를 명시한다.
- 관리자 작업과 문서 버전 전환을 감사 로그에 기록한다.
- 외부 공개 배포 전에는 SSO/RBAC, HTTPS, 보안 헤더, 비밀 저장소, 백업 암호화와 취약점 점검을 추가한다.

## 20. 졸업작품 발표에서 강조할 연구 요소

1. **한국어 학사 도메인의 하이브리드 검색**: BM25, dense, RRF, reranker의 Hit@K·MRR·nDCG 비교
2. **페이지·표 인식 청킹**: 고정 길이 청크와 페이지/표 헤더 보존 청크의 페이지 정확도 비교
3. **근거 기반 abstention**: 답변 가능률과 미근거 답변률 사이의 trade-off 및 calibration
4. **문장별 출처 검증**: 단순 출처 목록과 claim-evidence 검증 방식의 출처 일치율 비교
5. **문서 버전·현재성 처리**: 과거 자료와 현재 질문을 구분하는 temporal hard negative 실험
6. **API 독립성**: 생성 API가 없어도 완전한 검색·출처 디버그와 평가가 가능한 구조
7. **실제 문서 난점 대응**: 이미지형 표, 한컴 제어문자, 병합표, 물리/인쇄 페이지 차이를 재현 가능한 fixture로 사용

발표 실험은 `BM25 → Dense → Hybrid → Hybrid+Reranker → +Abstention → +Citation Verification`의 누적 ablation으로 구성하고, 품질뿐 아니라 검색 지연시간, 메모리, LLM 비용을 함께 제시한다.
