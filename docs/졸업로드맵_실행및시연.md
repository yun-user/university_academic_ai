# 개인별 졸업 로드맵 — 실행과 시연

2018~2026학번 홍익대학교 세종캠퍼스 소프트웨어융합학과 학생이 입력한 이수내역으로 부족한 요건과 학기별 계획을 확인하는 로컬 프로그램이다. 상단에서 입학연도와 심화·일반과정을 선택하며 실제 과정 변경에는 학교 승인이 필요하다. 학교의 공식 졸업판정을 대신하지 않는다. 학번을 바꾸면 이수내역은 유지하고 승인·대체인정 확인은 초기화한다.

## 실행

별도 프론트엔드·백엔드·DB를 사용하는 졸업작품 버전은 **`setup_web.cmd` → `start_web.cmd` → http://127.0.0.1:8000** 순서로 실행한다. [React/FastAPI/SQLite 웹앱 설명](졸업로드맵_웹앱구조와시연.md)에 API·DB·LLM 상담 시연을 정리했다. 아래는 기존 Streamlit 독립 실행본 사용법이다.

Windows에서 Python 3.11 이상이 필요하다. 제공한 ZIP을 모두 풀고 `setup_planner.cmd`를 실행한 다음 `start_planner.cmd`를 실행한다. 설치 단계에는 패키지를 내려받을 인터넷 연결이 필요하다. 브라우저에서 `http://127.0.0.1:8503`을 연다.

이미 프로젝트 가상환경이 준비되어 있다면 `start_planner.cmd`만 실행한다. 포트가 사용 중이면 이전 실행 창을 종료하거나 아래 명령에서 포트를 변경한다.

```powershell
.venv/Scripts/python.exe -m streamlit run planner_app.py --server.address 127.0.0.1 --server.port 8503
```

독립 실행본의 기본 계산은 임베딩 모델, OCR, 외부 AI 키가 필요 없다. LLM 맞춤 추천은 별도로 켜서 사용한다. 기존 전체 앱은 `start.cmd`로 실행하며 검색 기능과 로드맵 메뉴를 함께 사용할 수 있다.

## 학교 성적을 한 번에 가져오기

Codex 내부 브라우저에서 학교 클래스넷에 로그인하고 전체성적조회를 연다. 첫 학기 제목부터 마지막 학기까지 표를 한 번에 복사해 `학교에서 이수내역 가져오기 → 전체성적조회 내용 붙여넣기`에 넣고 확인한다. 미리보기에서 학기·과목 수, 이수구분·교양영역·설계학점·재수강을 확인하고 적용한다. Codex에게 과목 표를 로드맵으로 옮겨 달라고 요청할 수도 있다.

별도 Chrome/Edge 로그인 창도 선택할 수 있지만 2026-10-07 학교 보안 확인·반복 새로고침이 발생하여 이 접속 경로는 정상 동작을 보장하지 않는다. 문제 발생 시 연결을 종료하고 내부 브라우저/성적표 붙여넣기를 사용한다. 기존 설치에서는 `setup_planner.cmd`를 다시 실행하고 `start_planner.cmd`로 앱을 시작한다.

학수번호·과목명·학점·성적·수강시점은 자동으로 가져온다. 원 성적표에 없는 이수구분은 현재 교과과정과 정확히 일치할 때만 제안하며, 나머지는 미확인으로 남겨 계산에서 제외한다. 학교 비밀번호나 쿠키를 저장하지 않으며 LLM 전송은 별도 동의가 필요하다. 자세한 범위와 오류 대응은 `docs/졸업로드맵_학교연동.md`를 참조한다.

## LLM이 맞춤 로드맵을 추천하게 하기

1. 과목별 이수내역과 계획 조건을 입력한다.
2. ‘LLM 맞춤 추천 사용’을 켜고 희망 진로·수강 선호를 적는다. 예: ‘웹 개발에 관심이 있고 프로젝트 과목을 우선하고 싶어요.’
3. ‘LLM 연결 설정’에서 OpenAI API 키와 본인 계정에서 사용할 수 있는 모델명을 입력한다. 키는 화면에서 암호로 표시하고 세션에서만 사용한다. ChatGPT 로그인만으로 API 연결이 설정되지는 않는다.
4. ‘OpenAI에 전송할 요약 미리보기’를 확인하고 전송에 동의한다.
5. ‘LLM 맞춤 로드맵 생성’을 누른다. 실제 배치 과목, 추천 이유, 다음 확인 행동과 남은 졸업요건을 확인한다.

이미 설정한 `OPENAI_API_KEY`·`OPENAI_MODEL` 또는 OpenAI 공식 주소를 사용하는 `LLM_API_KEY`·`LLM_MODEL_NAME`도 읽을 수 있다. 타 서비스 주소용 키는 OpenAI로 보내지 않는다. 별도의 자동 접속 시험은 하지 않으며 실제 생성 버튼을 누를 때 요청 1회가 발생한다. 기존 `LLM_ENABLED=false`는 기본 검색의 설정이며, 로드맵의 명시적 사용 선택·전송 동의와 생성 버튼으로 이 기능을 실행한다.

전송 내용은 취득 인정된 학수번호·수강시점, 수강중 학수번호, 항목별 점검값, 후보 과목, 계획 조건과 희망 사항이다. 원 성적등급·이름·학번·대체인정 메모는 전송하지 않는다. 희망 사항과 직접 추가한 후보의 과목명에도 개인정보를 적지 않는다. `store=false`로 응답 저장을 끄지만 서비스 전체의 보관 정책을 대체하는 설정은 아니다. API 호출은 비용이 발생할 수 있다.

LLM은 후보 안에서 우선순위와 설명을 제안한다. 계산기가 학점·필수요건을 점검하고 우선순위에 최대 1.5배 가중치를 주어 조건에 맞게 배치한다. 제안 순서와 실제 배치 순서가 다를 수 있다. 목록 밖 과목·이미 취득한 과목·제외 과목·중복 제안이나 API 오류가 있으면 LLM 응답을 사용하지 않고 기본 계산 결과를 표시한다. 설명 문장은 모델의 참고 의견이며 수치·학교 승인 여부는 점검표와 학교에서 확인한다.

결과는 세션에 유지되므로 화면 재실행·다운로드만으로 API가 다시 호출되지 않는다. 입력 조건이 바뀌면 이전 결과를 숨긴다. 전체 백업에는 희망 사항을 포함하고 API 키·전송 동의는 포함하지 않는다. 백업 복원 후에는 다시 전송에 동의해야 한다.

## 입력과 사용

1. ‘가상 예제로 시작’을 눌러 동작을 익히거나 지정 CSV·수동 입력으로 이수내역을 작성한다. 이수내역의 학수번호는 앞자리 0을 유지한다.
2. 이수구분·교양영역·수강 당시 설계학점을 확인한다. 재수강은 인정할 한 건을 남기고 나머지는 인정제외로 표시한다.
3. 학교에서 확인한 개인 필수목록과 대체인정 관계를 입력한다. 대체인정은 적용 과정·수강기간·근거와 사용자 확인이 필요하다.
4. 졸업작품, 어학 제출, 일반과정 승인, 설계 이수순서와 인정 범위 등 수동 확인 항목을 점검한다.
5. 후보 표에서 실제 개설학기와 선수학수번호를 확인한다. 기본 후보의 개설은 현재 교과과정에 근거한 미래 가정이고 선수조건은 미확인이다.
6. 계획 시작 학기는 취득내역의 마지막 학기보다 뒤로 정한다. 학기 수·학점 한도를 정해 계산한다.
7. 과목별 추천 이유와 계획 후에도 남는 항목을 확인한다. 빈 학기가 나타나면 선수조건·개설학기·후보 누락·학점 한도를 대조한다.

## 저장 형식

| 버튼 | 내용 | 다시 불러오기 |
| --- | --- | --- |
| 입력한 이수내역 CSV 저장 | 성적·수강 시점·인정 구분 | CSV 적용 |
| 전체 입력 백업 JSON 저장 | 이수내역·과정·필수목록·대체인정·수동 확인·후보·추천 제외·계획 조건 | 화면 상단 전체 입력 복원 |
| 점검 결과와 로드맵 JSON 저장 | 현재 및 계획 후 계산 결과·출처·가정 | 결과 기록용, 복원용 아님 |
| 인쇄용 보고서 HTML 저장 | 현재/계획 후 비교표·학기별 계획·남은 항목·출처 | 브라우저에서 열어 인쇄/PDF 저장 |

전체 입력 백업은 v2 형식이다. v1 결과 JSON에는 이수내역과 후보 전체가 없어 복원할 수 없다. 백업을 복원하면 기존 화면 입력을 대체한다. 저장 당시와 기준 자료가 다르면 안내하고 현재 규정으로 재계산한다. 입력 자료는 서버 파일에 자동 저장하지 않으므로 새로고침 전에 직접 백업한다. 다운로드한 파일에는 본인의 성적·근거가 포함될 수 있다.

## 5분 시연 순서

| 시간 | 화면과 행동 | 설명할 내용 |
| --- | --- | --- |
| 0:00~0:40 | 대상과 가상 예제 | 2020학번 두 과정, 합성 21학점 예제이며 실제 학생 정보가 아님 |
| 0:40~1:30 | 심화·일반 전환 | 전공·MSC 기준의 차이, 일반과정 변경 승인 필요 |
| 1:30~2:10 | 현재 점검표 | 총학점과 필수과목·영역·수동 확인을 분리 |
| 2:10~3:10 | 후보와 계획 계산 | 입력 선수조건·학기 개설·학점 한도, 추천 이유와 미충족 결과 |
| 3:10~4:00 | 백업 저장·새로고침·복원 | 개인 입력을 사용자가 보관하고 현재 규정으로 재계산 |
| 4:00~4:40 | 인쇄용 보고서 | 현재/계획 후 비교와 근거 확인 |
| 4:40~5:00 | 합성 평가 결과와 한계 | 자동 테스트와 실제 학사 판정 정확도를 구분 |

학과에서 확인하지 않은 관계를 실제 대체과목인 것처럼 시연하지 않는다. 임의 관계를 시험한다면 과목코드와 근거에 ‘가상’임을 명확히 표시한다.

## 재현 검증

```powershell
.venv/Scripts/python.exe -m scripts.evaluate_planner
```

`output/planner/evaluation`에 32개 합성 사례 결과가 생성된다. 18개 학번·과정 조합을 포함하며 기대 결과와 실제 결과가 다르면 종료코드 1을 반환한다. 이는 구현의 계산 검증이며 실제 학생 대상 정확도 수치가 아니다.

전체 저장소에서는 `python -m pytest -q`로 기존 기능을 포함해 검사한다. 독립 실행본에는 로드맵 테스트만 포함되며 pytest를 설치한 뒤 실행할 수 있다. Windows에서 기존 테스트 임시폴더가 잠기면 기존 폴더를 강제 삭제하지 말고 `--basetemp=new-run -o cache_dir=new-cache`처럼 새 테스트 폴더를 지정한다. 중첩된 임시 경로를 지정한다면 부모 폴더를 먼저 생성한다.

2026-10-05 검증: LLM 추가 후 전체 저장소 399개 통과. API 응답은 모의 검증으로 실제 과금 호출은 수행하지 않았다. Windows Python 3.12.14의 확인된 의존성 목록은 `requirements-planner-tested.txt`다. 설치 스크립트는 `requirements-planner.txt`의 호환 범위를 사용한다. 새 PC 최초 설치와 HTML 보고서의 실제 인쇄 배치는 추가 검수해야 한다.

2026-10-06에는 압축을 푼 별도 실행본의 테스트 96개도 통과했다. 이 검사는 같은 PC의 기존 가상환경을 사용했다.

같은 날 학교 성적 가져오기 추가 후 전체 회귀 테스트 430개가 통과했다. 이후 브라우저 작업 스레드·종료/오류 정리 테스트 2개를 추가하고 관련 단위 테스트 31개를 통과했다. 학교 연동 검증 범위는 `docs/졸업로드맵_학교연동.md`를 참조한다.

2026-10-07 내부 브라우저 성적표 붙여넣기 추가 후 전체 회귀 테스트 443개 통과. 이후 화면 배치 변경의 UI 테스트 10개 통과. Codex 내부 브라우저에서 실제 과목 표를 미리보기로 가져오는 경로를 확인했으며, 개인 인정구분 확정·적용과 실제 LLM 호출은 별도 단계다.
