# 출처를 보여주는 대학 학사정보 AI 도우미

Python으로 실행하는 로컬 졸업작품용 앱입니다. 기존 학교 자료 검색에 한국어 BM25 검색, 문서 관리, 공개 공지 수집, OCR 검토, 출처 검증과 평가 화면을 추가했습니다.

## 1. 처음 실행

1. 압축을 **모두 풀고**, 압축 밖의 프로젝트 폴더를 엽니다.
2. Python 3.11 이상이 설치되어 있어야 합니다. 검증 환경은 Windows / Python 3.12입니다.
3. `setup.cmd`를 실행합니다. 가상환경·패키지·임베딩 모델·OCR 언어 데이터를 준비합니다. 최초 실행에는 인터넷과 충분한 디스크 공간이 필요합니다.
4. 설치가 끝나면 `start.cmd`를 실행합니다.
5. 브라우저의 `http://127.0.0.1:8501`에서 질문합니다. 종료는 실행 터미널의 Ctrl+C입니다.

PowerShell에서는 다음과 같이 실행할 수도 있습니다.

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\setup.ps1
powershell -NoProfile -ExecutionPolicy Bypass -File .\start.ps1
```

스크립트의 실행 정책 지정은 해당 PowerShell 프로세스에만 적용됩니다. 검색과 기본 답변에는 API 키가 필요하지 않습니다. 모델을 다운로드한 뒤에는 기존 문서 검색을 오프라인에서 사용할 수 있습니다.

`py` 실행기가 없어도 설치 스크립트가 `python`, `python3`, 등록된 설치 경로를 찾습니다. 일반 Python이 없고 Codex 데스크톱의 호환 Python이 있으면 마지막 대안으로 사용합니다. 직접 설치한 Python을 선택하려면 환경변수 `ACADEMIC_PYTHON`에 `python.exe`의 전체 경로를 지정하세요. 어느 경로에도 Python 3.11 이상이 없으면 설치 안내를 표시합니다.

## 2. 질문과 출처 확인

- `학수번호 001009 교과목 정보`처럼 학수번호 또는 전체 과목명을 입력하면 CSV에서 정확히 조회합니다.
- `소프트웨어융합학과 2학년 1학기 전공필수 과목`은 조건에 맞는 전체 과목을 반환합니다.
- 일반 질문은 한국어 의미 검색과 BM25 키워드 검색을 합칩니다. 적용 학과와 문서 유형을 선택할 수 있습니다.
- 학사 규정은 관련 용어와 적용 조건을 확인하는 별도 검색·답변 경로를 유지합니다.
- 출처에는 문서명, PDF 실제 페이지 또는 CSV 데이터 행, 기준연도, 최신 여부가 표시됩니다.
- **CSV 데이터 행은 머리글을 제외한 1부터 시작합니다.** 따라서 CSV 데이터 2행은 일반 편집기에서 파일의 3번째 줄에 해당합니다. 여러 줄 셀이 있으면 실제 텍스트 줄 번호와는 다릅니다.
- PDF 쪽수는 파일의 실제 페이지 순서입니다. 책자에 인쇄된 쪽수와 다를 수 있습니다.
- 웹 공지는 공식 출처 링크를 함께 표시합니다. 수집일과 게시일은 별개의 메타데이터입니다.
- 검색 유사도는 정답 확률이 아닙니다. 자료가 오래되었거나 적용 학번을 확인할 수 없으면 담당 부서 확인이 필요합니다.

## 3. 관리자 로그인과 자료 등록

`setup.cmd`가 프로젝트의 `.env`에 임의의 `ADMIN_PASSWORD`를 생성합니다. 해당 값을 로컬 편집기로 확인해 관리자 화면에 입력하세요. `.env`는 ZIP과 Git에 포함하지 않습니다. 이미 설정한 값은 유지합니다.

1. 왼쪽 **문서관리**를 엽니다.
2. 관리자 비밀번호로 로그인합니다.
3. PDF·CSV·TXT를 선택하고 학과, 문서 유형, 기준연도, 발행기관, 출처를 입력합니다.
4. 새 버전이면 교체할 기존 자료를 선택합니다. 원본 파일은 삭제하지 않습니다.
5. 등록 후 **검색 데이터 반영**을 실행합니다.

CSV·TXT는 UTF-8로 저장하세요. 업로드는 최대 50MB, PDF는 최대 1,000쪽이며 암호화된 PDF는 받지 않습니다. CSV 교과과정의 구조화 조회는 제공된 교과과정 CSV와 같은 열 구성을 사용해야 합니다. 임의 CSV는 일반 검색용으로 처리합니다.

비활성화·재활성화도 **검색 데이터 반영** 후 검색 결과에 적용됩니다. 최신 여부와 입학연도는 관리자가 문서에서 확인해 입력해야 하며, 단순히 가장 최근 문서라고 모든 학번에 적용되는 것은 아닙니다. 입학연도 메타데이터는 보존하지만 모든 문서의 개별 규정 적용 범위를 자동으로 판정하지는 않습니다.

업로드 원본은 `data/uploads`, 등록·검토·감사 기록은 `data/catalog/registry.sqlite3`에 저장됩니다. 오류 보고서는 `data/processed/ingestion_report.json`에서 확인할 수 있습니다.

## 4. 공개 공지 수집

1. **공개공지수집**에서 공식 사이트의 정확한 호스트를 허용 도메인에 입력합니다. 예: `www.hongik.ac.kr,software.hongik.ac.kr`.
2. 게시판 목록이 아닌 **개별 공지 본문 URL**을 입력합니다.
3. `article` 또는 `main`으로 본문을 찾을 수 없으면 사이트의 본문 CSS 선택자를 입력합니다.
4. 미리보기에서 본문과 원문 링크를 확인하고, 게시일·적용 학과를 입력하여 등록합니다.
5. 문서관리에서 **검색 데이터 반영**을 실행합니다.

공지는 한 건씩 검토하여 등록합니다. 전체 게시판 자동 순회나 로그인 페이지 수집은 지원하지 않습니다. 본문 HTML 스냅샷과 추출 텍스트, 공식 URL, 수집 시각을 보존합니다. robots.txt 확인 실패·수집 금지·비공개 주소·과도한 리다이렉트·로그인 화면은 처리하지 않습니다. HTTP 429 응답이면 재시도를 멈춥니다. HTTPS 인증서 검증을 유지하며, 검증한 공개 IP로 연결해 내부 주소 접근을 막습니다.

## 5. 스캔 PDF OCR

한국어·영어 언어 데이터는 설치 과정에서 준비합니다. 실패했다면 다음을 실행하세요.

```powershell
.\.venv\Scripts\python.exe -m scripts.setup_ocr
```

1. **OCR검토**에서 PDF와 실제 페이지 번호를 선택합니다.
2. **이 페이지 OCR 실행**을 누릅니다.
3. 왼쪽 원본 이미지와 오른쪽 텍스트를 대조합니다. 표의 열·행, 숫자, 학점, 예외 조건은 직접 확인합니다.
4. 필요하면 텍스트를 수정하고 확인란을 체크한 뒤 저장합니다.
5. 문서관리에서 검색 데이터를 반영합니다.

승인하지 않은 OCR은 검색에 들어가지 않습니다. 원본 PDF의 해시가 달라져도 이전 승인 결과를 적용하지 않습니다. OCR은 구조화된 표 복원을 보장하지 않으므로, 교과과정 표는 검토된 CSV로 등록하는 것이 좋습니다. 기존 스캔 자료 전체의 검토는 자동 승인하지 않았습니다. 설계교과목 PDF 1쪽에는 동작 확인용 미승인 OCR 결과가 있습니다.

## 6. 선택적 LLM

기본 답변은 원문을 정리해 보여주며, 외부 API를 호출하지 않습니다. LLM을 사용하려면 `.env`를 설정한 뒤 앱을 재시작하세요.

```dotenv
LLM_ENABLED=true
LLM_PROVIDER=openai_compatible
LLM_MODEL_NAME=사용할_모델_ID
LLM_API_KEY=본인의_API_키
LLM_BASE_URL=사용하는_호환_API의_기본_URL
```

기본 OpenAI 서비스라면 `LLM_BASE_URL`을 비워 둡니다. 선택한 서비스는 Chat Completions와 `temperature=0` 호출을 지원해야 합니다. 지원하지 않으면 기본 답변으로 전환됩니다. 실제 API 키를 공개하거나 소스에 넣지 마세요.

LLM은 검색 근거에서 관련 문장을 선택하고 정리합니다. 각 문장은 인용한 청크 원문에 실제로 포함되어야 하며, 출처는 프로그램이 연결합니다. 검증할 수 없는 재작성·허위 출처·원문 밖 숫자·통신 오류는 기본 답변으로 전환합니다. CSV 과목 목록은 LLM이 수정하지 않습니다. 이 검사는 인용문 존재를 보장하지만, 질문에 대한 완전한 관련성이나 빠진 조건까지 보장하지는 않습니다.

## 7. 평가와 개발

```powershell
.\.venv\Scripts\python.exe -m pytest -q
.\.venv\Scripts\python.exe -m scripts.evaluate --split dev
.\.venv\Scripts\python.exe -m scripts.evaluate --split test
```

`evals/regression.jsonl`에는 120개 회귀 질문이 있습니다. 114개는 등록된 CSV의 과목명·학수번호에서 생성한 질문이고, 6개는 자료 범위 밖의 질문입니다. 동일 과목의 질문은 dev/test로 나누어 섞지 않습니다. dev에서 설정을 결정하고 test 결과를 보고 다시 조정하지 마세요.

**평가결과** 화면에서 Hit@K, MRR, 확인 불가 질문 거절률과 질문별 결과를 확인합니다. 이번 평가의 높은 값은 한정된 자동 생성 질문에 대한 결과입니다. 실제 학생 질문에 대한 일반적인 정확도로 발표하면 안 됩니다. 졸업·장학·복학·예외 규정과 서로 다른 학번이 포함된 질문을 사람이 검토해 추가해야 합니다.

검색 설정은 `SEARCH_MODE=hybrid` 또는 `dense`, `DENSE_TOP_K`, `KEYWORD_TOP_K`, `RRF_K`, `DENSE_WEIGHT`, `KEYWORD_WEIGHT`, `MIN_RETRIEVAL_SCORE`로 조정합니다. 하이브리드 모드는 키워드 일치 비율이 너무 낮으면 답변을 보류하므로 다른 표현의 질문에서 누락이 생길 수 있습니다. 순위 합산 점수는 확률로 표시하지 않습니다.

## 8. 범위와 보관

이 버전은 한 컴퓨터에서 실행하는 졸업작품용 완성 앱입니다. 학교 전체 사용자를 위한 공개 서비스 배포, SSO, 사용자별 권한, 개인정보가 담긴 학생 기록 처리는 별도 작업입니다. 서버 기본 주소는 `127.0.0.1`입니다.

원본과 메타데이터를 백업하세요. 색인 반영은 프로세스 간 잠금으로 직렬화하지만, Chroma 전체 갱신 중 시스템 전원이 끊기는 상황까지 원자적 롤백을 보장하지는 않습니다. 전처리·임베딩 준비 오류는 이전 색인을 유지하며, 중간 저장 장애가 발생한 경우 `python -m scripts.prepare`를 다시 실행해 원본으로 복구합니다.

초기 저장소의 계획서는 장기 계획으로 보존했습니다. 현재 기능과 검증 결과는 이 설명서와 `검증결과.md`를 기준으로 보세요.
