# 설계학점 자동 반영 · 2026-10-09

## 원인과 변경

기존 추천 후보에는 설계학점이 있었으나 전체성적표에서 가져온 이수 과목에는 설계학점 열이 없어 0으로 저장되었다. 졸업계산은 그 0을 그대로 합산했다. 이제 계산 시 학과 공개표와 이수 과목의 학수번호·과목명·교과학점을 대조하여 설계학점을 별도로 배분한다. 기존 DB 내역도 불러오기·재계산하면 적용되며 원래 성적표 값은 유지한다.

이수내역에 설계학점 열, 과목별 현재 합산값·근거를 추가했다. 상세 편집에서 ‘설계학점 직접 지정’을 켜면 0을 포함한 사용자 값을 우선하며, 해제하면 자동 대조로 돌아간다. 기존 양수 입력은 직접 입력으로 보존한다. DB v3→v4는 입력 방식 열만 추가하며 CSV·전체 JSON 백업에도 보존한다. 졸업현황·HTML 보고서·AI 설명 문맥은 같은 계산 결과를 사용한다.

설계학점은 교과학점 중 설계 부분이다. 총 졸업학점에 다시 더하지 않는다. 기초설계 2 + 종합설계 3 + 3 = 8이며, 요소설계 4 이상을 추가해야 12가 된다.

## 적용 범위

- 2019~2026년 수강내역에 현재 공개표를 **참고 대조**한다. 이 범위는 앱의 검토 범위이며 학과 표의 공식 시행기간을 뜻하지 않는다. 2018학번도 수강연도가 해당 범위이면 대조한다.
- 현재 페이지에는 시행연도·중간 개정 이력이 명시되지 않았다. 이전 검색 답변의 ‘2019학년도 1학기부터 적용’ 확정 표현을 제거했다. 2018년 이전·2027년 이후 수강 과목은 수강 당시 자료로 직접 확인·입력한다.
- 공백, 데이타/데이터 표기, 끝의 영어강의 `(*)`·`(C)` 표시만 정규화한다. 명칭 변경·대체인정·동일과목 코드만으로 설계학점까지 자동 인정하지 않는다.
- 전공 이수구분을 확인한 취득 내역만 합산한다. F/NP·미확정·수강중·인정제외·중복·영어 추가학점은 현재 설계 합계에서 제외한다.
- 기초→요소→종합 이수순서, 개인별 설계 인정과 대체·예외 승인은 학교 확인 대상이다. 학점의 참고 합계 충족은 최종 졸업판정이 아니다.
- 일반과정에도 과목별 설계 배분 근거를 보여주지만 심화의 설계 12학점 요건을 일반에 강제하지 않는다.

## 사용 순서

1. 앱을 재시작하거나 새로고침하고 저장한 계획을 불러온다.
2. 이수 과목에서 이수구분이 미확인이면 ‘학과 자료로 분류 확인’ 후 근거를 보고 적용한다.
3. 설계학점 열과 ‘설계학점 근거’를 확인한다. 학교에서 다른 값을 인정한 경우 상세 편집에서 직접 지정한다.
4. ‘졸업요건 계산’을 누르면 나의 졸업 현황에서 설계 합계와 과목별 근거를 볼 수 있다.

## 검증

합성 입력으로 공식 표 12행·전체 설계 18/교과 36학점, 6과목 설계 12학점 예시, 수강연도 경계, 번호·이름·교과학점 불일치, F/NP·중복 등 제외, 직접 0 지정과 자동 복귀, CSV·DB·백업·보고서·API 일치, v2/v3 DB 이전을 검사한다. 브라우저 검증과 배포본 결과는 README의 최신 검증 기록을 참조한다. 실제 학생의 공식 졸업사정 정확도 평가와는 별개다.

최종 구현 검사: 전체 Python 642개(분할 실행)·프론트엔드 7개 통과, TypeScript/Vite 빌드 성공, 합성 평가 32/32. 브라우저에서 가상 6과목의 설계 합계 12, 기초설계 직접 0 지정 후 10, 해제 후 12, DB 저장·불러오기 재계산을 확인했다. 의존성의 폐기 예정 API 경고 2건은 기존과 동일하다.
