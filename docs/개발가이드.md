# 개발 구성

## 처리 흐름

원본 PDF/CSV/TXT 및 관리자 등록 자료 → 통합 corpus → 청크 → E5 임베딩 및 Chroma → 조건/과목 정확 조회 또는 BM25+Dense RRF → 기본 발췌 답변/선택적 LLM 인용 선택 → 원문과 출처 표시.

## 주요 추가 파일

| 파일 | 책임 |
|---|---|
| `src/retrieval/keyword_search.py` | Kiwi 토큰화, Okapi BM25, content hash로 검증하는 토큰 캐시, 가중 RRF |
| `src/ingestion/registry.py` | SQLite 등록부, 원본 보존, 버전 교체, 활성화, OCR 적용, 감사 기록 |
| `src/ingestion/web_collector.py` | 공식 HTTPS 공지 수집, 본문 선택자, robots, URL/공개 IP 검증 |
| `src/ingestion/ocr.py` | PyMuPDF/Tesseract OCR, 페이지 원본 미리보기, 검토·승인 |
| `src/operations.py` | 프로세스·세션 간 corpus/검색 작업 잠금 |
| `src/runtime.py` | Streamlit 공용 검색 서비스와 문서 반영 |
| `src/admin_auth.py` | 로컬 관리자 로그인 |
| `src/evaluation/metrics.py` | 출처 위치 Hit@K, MRR, 범위 밖 질문 거절률 |
| `pages/` | 문서 관리, 공지 수집, OCR 검토, 평가 결과 |
| `scripts/initialize.py` | 기존 비밀값을 보존하는 최초 설정 |
| `scripts/prepare.py` | 원본 전처리 후 검색 색인 반영 |
| `scripts/setup_ocr.py` | 공식 Tesseract 언어 데이터 설치 및 해시 기록 |
| `scripts/build_evaluation.py` | CSV 기반 고정 그룹 회귀 질문 생성 |
| `scripts/evaluate.py` | 동일 임베딩으로 두 검색 모드를 비교하고 JSON 저장 |

## 기존 코드 변경

- `DocumentSearchService`: 하이브리드 검색 선택, 과목명/학수번호 정확 조회, 공식 웹 규정 허용, 범위 밖 질문 보류.
- `build_corpus`: 원본 읽기 기능을 유지하고 관리자 등록·비활성 상태와 승인한 OCR을 병합.
- `AnswerSource`: 공식 URL을 추가하고 검색 원본과 메타데이터 일치를 검증.
- `LLMAnswerService`: LLM이 지정한 각 quote가 해당 청크 원문에 있는지 검사. 검증 불가 재작성은 기본 답변으로 전환.
- `app.py`: 공유 검색 서비스와 공식 URL 링크 연결, 출처 검증된 답변 표시.
- `.streamlit/config.toml`: localhost 서버, 업로드 제한, 기본 테마.

## 설계 선택

BM25는 작은 학사 corpus에서 점수와 토큰 처리를 검토하기 쉽도록 Python으로 구현했습니다. Kiwi 형태소와 원시 단어·학수번호를 함께 유지하며, 규정의 부정 표현을 불용어로 지우지 않습니다. 별도 키워드 DB의 수동 동기화 대신 Chroma의 활성 청크 ID/해시로 토큰 스냅샷을 검증해 재생성합니다. RRF는 순위를 합칠 뿐 검색 유사도 값을 확률로 바꾸지 않습니다.

정확 과목 조회와 기존 학사 규정 경로는 별도로 유지합니다. 공개 공지는 TXT 저장 형식을 사용하지만 URL과 문서 유형 `공개공지`가 있어야 규정 답변에 사용할 수 있습니다. 일반 학교정보 TXT는 규정 단독 근거로 승격하지 않습니다.

사용자가 업로드한 원본은 고유 ID 디렉터리에 보존합니다. 이전 버전은 활성 상태만 변경하며 자동 삭제하지 않습니다. 스캔 PDF에 OCR 텍스트를 덮어쓰지 않고 문서 ID·원본 해시·페이지에 대응하는 승인 결과를 별도로 저장합니다.

LLM은 자유로운 재작성보다 검증할 수 있는 원문 선택에 제한했습니다. 출처 ID만 존재한다고 답변 의미까지 보장되는 것은 아니기 때문입니다. 문장을 자연스럽게 재작성하는 기능을 확대하려면 조건 누락·부정 반전·숫자 단위·각 주장과 근거의 함의 관계에 대한 별도 평가가 필요합니다.

## 로컬 개발

```powershell
.\.venv\Scripts\python.exe -m pytest -q
.\.venv\Scripts\python.exe -m scripts.prepare
.\.venv\Scripts\python.exe -m streamlit run app.py
```

외부 API를 호출하지 않는 테스트입니다. 실제 모델을 사용한 평가는 준비된 색인과 다운로드된 임베딩 모델이 필요합니다. `requirements-tested-py312-windows.txt`는 검증 환경의 정확한 버전 기록이며 Python/OS가 다르면 일반 `requirements.txt`를 사용하세요.

GitHub 원격 저장소에는 변경을 업로드하지 않았습니다. 전달한 폴더의 수정 파일을 기존 저장소 작업 브랜치에 반영하고 테스트한 후 커밋할 수 있습니다. `.env`, 원본 추가 업로드, registry DB, 검색 색인, 모델 캐시는 커밋에서 제외합니다.
