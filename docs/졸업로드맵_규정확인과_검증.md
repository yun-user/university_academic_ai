# 졸업 로드맵 규정 확인과 검증

대상은 2020학번 홍익대학교 세종캠퍼스 소프트웨어융합학과의 단일전공 신입학 학생이다. 심화·일반과정을 구분한다. 이 문서는 제출 전 검증 절차이며 학교의 졸업 승인 자료가 아니다.

## 학교 자료와 대조할 항목

| 항목 | 기록할 내용 | 현재 처리 |
| --- | --- | --- |
| 적용 범위 | 입학연도, 학과, 과정, 전과·편입 여부 | 2020학번 심화·일반 단일전공만 지원 |
| 필수목록 | 원래 학수번호, 수강 당시 교과과정, 개정·폐지 여부 | 사용자가 확인한 목록 입력 |
| 동일과목 | 두 코드가 재수강·중복 인정상 같은 과목인지 | 동일과목코드로 묶고 여러 취득 건은 보류 |
| 선택 대안 | 중 하나를 선택하면 되는 요건인지 | 이미 취득·수강중이면 다른 대안을 자동 추천하지 않음 |
| 대체인정 | 원래 필수과목, 대체 이수과목, 과정, 인정 수강기간, 근거 | 사용자 확인한 한 방향 관계만 필수요건에 적용 |
| 이수구분·설계학점 | 실제 수강연도에 인정되는 구분과 설계학점 | 사용자가 확인해 입력; 대체관계로 자동 변경하지 않음 |
| 선수조건 | 선수과목과 동시수강 허용 여부 | 입력된 이전 학기 이수 조건만 적용; 동시수강 미지원 |
| 개설 여부 | 실제 계획 학기의 개설 목록 | 기본 후보의 미래 개설은 가정 |
| 지정 교양·기초영어 | 학점 외 지정 과목 인정 여부 | 이수구분별 학점 계산만 지원; 지정 과목은 별도 대조 |
| 기타 졸업사정 | 평점, 등록학기, 졸업작품, 공학인증 세부 요건 | 학교 최종 확인 필요 |

학과에 확인할 때에는 아래 양식을 사용한다. 이름·학번·개인 성적은 프로젝트 문서나 공개 사례에 복사하지 않는다. 문의 전송은 사용자가 직접 한다.

```text
대상: 2020학번 / 소프트웨어융합학과 / 심화 또는 일반
원래 필수과목 학수번호:
대체 이수과목 학수번호:
인정되는 대체과목 수강기간: ____년 ____학기 ~ ____년 ____학기
기간 제한이 없다면 그 근거:
필수요건 대체 / 동일과목 중복 인정 / 선수조건 면제 중 어떤 관계인지:
학점·이수구분·설계 인정학점이 바뀌는지:
확인 근거: 공지 제목, 게시일, URL 또는 학과 확인일
```

## 대체인정 기능 사용

1. 이수내역에는 실제 취득한 과목 코드·학점·성적·수강연도·학기를 입력한다.
2. 개인 필수목록에는 원래 필수과목 번호를 입력한다.
3. `학교에서 확인한 대체과목 인정`에서 원래 과목과 실제 대체과목, 적용 과정, 시작·종료 기간, 근거를 등록한다.
4. 본인의 과정·2020학번·수강기간에 적용됨을 확인한 경우 확인란을 선택한다. 확인하지 않은 관계는 기록만 하고 계산에는 적용하지 않는다.
5. 현재 점검표의 해당 필수요건과 `현재 점검에 적용된 대체인정 근거`를 확인한다. 학점 합계는 실제 이수내역 기준이다.
6. 로드맵 결과 JSON에는 입력한 관계와 적용 내역이 포함된다. 다시 불러올 때는 별도의 ‘전체 입력 백업 JSON 저장’으로 만든 v2 백업을 사용한다. 이 백업은 이수내역·과정·필수목록·대체인정·확인 상태·후보·계획 조건을 복원한다. CSV에는 이수내역만 포함된다.

시작·종료 기간은 양 끝을 포함하며, **대체과목을 수강한 시점**에 적용한다. 학기 입력값은 1=1학기, 3=하계, 2=2학기, 4=동계이고 계산은 이 순서를 따른다. 종료 시점 제한 없음은 이를 확인한 경우에만 선택한다.

대체인정은 입력한 실제 대체과목 코드에만 적용한다. A를 B로 대체하고 B를 C로 대체한다고 해서 C로 A까지 인정하지 않는다. 동일과목의 별칭으로 대체인정 범위를 자동 확장하지도 않는다. 그 경우 정확한 실제 코드에 대해 추가 확인한 관계를 입력한다.

## 합성 사례와 기대 결과

아래 OLD, NEW, NEXT는 테스트용 가상 코드다. 실제 학교 인정 관계가 아니다. 기본 조건은 일반과정에서 `NEW → OLD`, 인정 기간은 2024년 2학기부터 2025년 1학기까지다.

| 입력 사례 | 기대 결과 |
| --- | --- |
| NEW를 2024년 하계에 취득 | 기간 이전이므로 OLD 미충족 |
| NEW를 2024년 2학기에 취득 | OLD 충족, 실제 NEW의 학점만 합산 |
| NEW를 2024년 동계에 취득 | OLD 충족 |
| NEW를 2025년 1학기에 취득 | 종료 시점 포함, OLD 충족 |
| NEW를 2025년 하계에 취득 | 기간 이후이므로 OLD 미충족 |
| 동일한 관계를 심화과정에서 조회 | 일반과정 관계는 미적용 |
| 학교 확인 표시가 없는 관계 | 경고 표시, 관계 미적용 |
| NEW가 F·미확정·수강중·인정제외 | 현재 판정에서는 대체인정 불가 |
| NEW의 취득 내역이 중복 | 중복 판정 해소 전 대체인정 불가 |
| OLD만 취득하고 NEW를 필수로 지정 | 반대 방향의 인정 불가 |
| OLD와 NEW를 모두 취득 | 대체라는 이유만으로 중복 학점에서 제외하지 않음 |
| NEXT의 선수과목이 OLD | NEW의 필수요건 대체만으로 선수조건 면제 불가 |
| 인정 기간이 끝난 뒤의 미래 학기에 NEW 추천 | OLD 충족으로 처리하지 않음 |

## 시험 계획과 한계

| 구분 | 검증 대상 | 통과 기준 |
| --- | --- | --- |
| 단위 시험 | 기간 경계·하계/동계 순서·방향·과정·중복·성적·근거 누락 | 모든 합성 사례의 기대 결과 일치 |
| 계획 통합 시험 | 미래 수강시점의 대체인정과 선수조건 분리 | 필수 충족 결과와 미배치 사유가 서로 모순되지 않음 |
| 화면 시험 | 등록·삭제·과정 전환·근거 표시 | 입력 상태 유지, 다른 과정의 관계 미적용, 화면 예외 없음 |
| 회귀 시험 | 기존 검색·문서처리·로드맵 | 전체 자동 테스트 통과 |
| 실제 규정 평가 — 미완료 | 학교에서 확인된 비식별 사례와 수작업 판정 | 과정별 정상·예외 사례의 항목별 결과를 대조하고 불일치 원인 기록 |

자동 테스트 통과는 구현 검증이다. 규정 자체의 정확성을 검증한 수치로 보고하지 않는다. 실제 규정 평가용 자료는 개발용 합성 사례와 분리하고, 학교 확인 전에는 정답률을 산출하지 않는다.
